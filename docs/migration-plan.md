# 剩余迁移推进计划

更新：2026-10-23。执行、验收与集成负责人：Winnie。参照固定版本 Dify 1.17.1、graphon 0.7.0；每项先核对原版与已有实现，优先复用。

目标是完成既定范围内的真实用户流程：编辑 → 调试 → 文件／人工输入／工具 → 多轮对话 → 发布 → 端用户运行 → 日志统计。功能事实以客户端 [`features.yaml`](../tool/features/features.yaml) 及其生成文档为准；本文规定推进顺序和验收，不另算一套完成率。

## 起点与范围

- 模型、代码、HTTP、分类器、参数提取和结构化输出已有服务端实现。后续复用，不从零重写。当前试用尚未配置模型插件进程、沙箱、HTTP 代理，不能以代码存在代替环境可用。
- 网页人工输入与邮件分别验收。网页已交付；邮件保持关闭，仍需独立收口。存储已完成，文件参与工作流、vision 和人工表单尚待接线。
- Chatflow 持久对话、工具执行、公开 Web/API 运行及其真实日志统计是主要剩余闭环。界面已有相应面板，不等于这些服务已完成。

## 阶段0：交付当前网页候选

1. 保留普通／富文本／Markdown 跨段换行、输入框本地选择和 Dify 选择菜单；按钮与画布拖动目标不参与被动文字选择。
2. 验证慢按后拖动和点击：页面选择区域先触发其按下计时后，画布仍能取回自己的焦点；注释编辑器的输入焦点不能被夺走。
3. 真浏览器覆盖指针／手模式右键、节点菜单、头像悬停、持久化移动、方向键、延迟同步、系统剪贴板。实际试用的 HTTP 与安全来源分别检查，不能用 localhost 的权限能力推断非安全 HTTP。
4. 更新冻结前端，核对所服务资源的哈希以及实际加载的 Dart Wasm/skwasm；保护现有账号、数据库、上传卷与密钥。发布证据区分源提交、运行代码提交和已知差异。

## 阶段0B：Android Web 移动端

依据用户 2026-10-23 的新增要求，排在执行依赖接通之前。复用 Flutter 手势识别和现有 Dify 菜单、输入与设计系统，不另写一套移动编辑器，不扩原生 APK。

1. 覆盖双指锚定缩放／平移、25%–200% 边界，空白单指平移、节点拖动和端口连线，手指数切换及系统取消不产生意外文档写入，连续手势不能被页面文字选择抢走。
2. 紧凑导航不占大半屏宽；顶部动作、节点／运行／变量面板与长按菜单可达。软键盘、面板滚动和文本编辑保留自身输入，横竖屏不覆盖桌面保存偏好。
3. 正式 Wasm 的真实浏览器多点触摸与页面→HTTP→持久结果验证，补桌面鼠标／键盘／触控板、选择和注释回归。区别 Chromium Android 仿真与真实手机／TalkBack／厂商浏览器，不冒称全部设备一致。
4. 更新同一试用前端、保留账号／数据库／上传卷／凭据和旧版本回滚；字体修复与永久回归现已按后续恢复指令交付。后续运行入口也沿用这些移动组件和检查，不以一次画布修复代替所有未来功能的移动验收。

## 阶段3A：持久 Chatflow

- 接真实 Chatflow 调试入口，保存 conversation、message、输入和状态，复用现有模型节点与 SSE 解码器。
- 多轮记忆和会话变量写入下一轮实际模型上下文；应用、工作区、账号／端用户、不同会话之间隔离。

- Workflow-as-Tool 绑定已发布快照，限定递归与调用深度，保留调用链和取消传播；公开端点在阶段4实现。
- 验收使用本地可控测试插件经过真实 daemon，验证所选凭据、动态参数、输出文件、拒绝／超时／取消、跨租户访问和递归限制。插件市场不随工具执行自动加入。

## 阶段4：公开 Web/API、端用户及运营记录

- 沿用当前版本存储和既定 `/v1` 映射，支持 blocking／streaming；公开页面复用现有表单、聊天和运行组件，不嵌入原版 Next.js 作为产品页面。
- 发布运行绑定冻结版本；修改草稿不影响已发布应用，再次发布才更新。site code、app API key、console 登录凭据是不同授权面。
- 端用户会话、文件、人工输入链接、停止与重载恢复保持隔离；禁用发布、轮换 key 和错误 key 都真实生效。
- 接 overview、工作流／会话日志和统计：只聚合实际 published app-run；草稿调试不混入公开访问数据，不补虚构统计。
- 验收：发布 → 两个端用户／两个 API 调用方独立运行 → 修改草稿与再次发布 → 停止／断线／重启 → 查询对应日志、token 和耗时；覆盖越权和失效授权。

## 阶段5：辅助服务

按入口组分别交付，不拆成逐按钮的小提交：

1. **生成器**：prompt／code／schema／workflow 实际调用现有模型边界，验证输出格式和协作应用结果，真实展示失败。
2. **TTS**：复用 daemon 的音色和音频接口，接语音列表、试听与播放；使用本地可控音频验证传输、错误和取消。
3. **主页 DSL 文件／URL 导入**：复用已有解析、版本确认和文档替换；URL 走受限 HTTP／SSRF proxy，验证类型、大小与失败不破坏原文档。不开启市场插件自动安装。
4. **标注语义匹配与命中历史**：沿既定 annotation-only 设计，复用固定 Weaviate 服务与现有 embedding 边界，窄接口可替换；不原地升级现有 PostgreSQL 卷，不扩展知识库。先取得固定原版向量后端／真实对照，按其阈值、top1、分数和过滤语义实现，不能用字符串近似或假命中替代。验证索引增删改、模型切换、失败状态、恢复和租户隔离。

## 统一验收与交付约定

- 每阶段先冻结一张场景矩阵，再提交完整候选。必须证明页面 → API／外部边界 → 持久状态 → 页面结果，包含失败与恢复，而不只报告筛选测试数量。
- 控制时钟／通道的确定性测试用于边界；独立进程重启、真实数据库和真实浏览器证明实际集成。模拟平台不等于真实 Mac／Safari，localhost 权限不等于实际试用来源。
- 数据丢失、越权、安全、错误结果和主流程不可用的问题立即修复。非阻断像素差异记录到既有清单，不持续打断运行主线；后续文字改动复用共享度量规则并运行控件回归，不加逐文案偏移。
- 变更影响范围内的单元／集成检查先通过；集成出口再跑适用全量、静态分析、design/features、正式构建和实际部署检查。失败日志保留；测试场景或标准修正必须说明原因，不能遮掉失败。
- 每个里程碑交源提交、运行版本、可试入口、支持／未支持范围及脱敏复现证据。更新现有 README、协议和唯一功能清单，任务送审；不以界面行数／测试数代替整体完成度。
- 保护当前用户账号、已确认编辑、数据库／上传卷及密钥；迁移以独立旧库夹具证明升级和恢复，不用清空真实试用数据换取通过。K8继续只作 Git 中继。
- 最终从干净安装与旧数据升级各跑一轮完整流程；文档配置、能力开关、实际运行和日志统计必须一致。正式公网发布不由开发试用更新自动推定。
