## 继续完善与待验

1. **实体设备**：Android Chrome 和 iOS Safari 的触摸、软键盘、文件选择、审批和画布仍待真机验收。已经取得的是 Chromium 桌面与 Android 视口下的真实触摸事件；不把它称为真机性能或 Safari 证据，本轮也不发布原生 iOS 包。

3. **证据范围**：补充原生控件截图使用原始 UI／等宽字体，长日志数据是英文执行记录、界面可为中文。WidgetTester 不提供真实系统的 CJK／emoji 等宽回退，不能用它宣称完整原生字体级联已验；Web 的 Unicode 组合、输入、复制和区域字形另有真实浏览器证据。
4. **运维复核**：备份仅恢复到新的隔离目标验证；回退只换可执行程序和网页资源，不覆盖备份之后的新写入。现行 SDK 的 service worker 是注销脚本，不是离线资源缓存；本轮热缓存证据准确标为 HTTP 缓存，运行标识与资源哈希一起核对。

## 统一验收与交付约定

- 每阶段先冻结一张场景矩阵，再提交完整候选。必须证明页面 → API／外部边界 → 持久状态 → 页面结果，包含失败与恢复，而不只报告筛选测试数量。
- 控制时钟／通道的确定性测试用于边界；独立进程重启、真实数据库和真实浏览器证明实际集成。模拟平台不等于真实 Mac／Safari，localhost 权限不等于实际试用来源。
- 数据丢失、越权、安全、错误结果和主流程不可用的问题立即修复。非阻断像素差异记录到既有清单，不持续打断运行主线；后续文字改动复用共享度量规则并运行控件回归，不加逐文案偏移。
- 变更影响范围内的单元／集成检查先通过；集成出口再跑适用全量、静态分析、design/features、正式构建和实际部署检查。失败日志保留；测试场景或标准修正必须说明原因，不能遮掉失败。
- 每个里程碑交源提交、运行版本、可试入口、支持／未支持范围及脱敏复现证据。更新现有 README、协议和唯一功能清单，任务送审；不以界面行数／测试数代替整体完成度。
- 保护当前用户账号、已确认编辑、数据库／上传卷及密钥；迁移以独立旧库夹具证明升级和恢复，不用清空真实试用数据换取通过。K8继续只作 Git 中继。
- 最终从干净安装与旧数据升级各跑一轮完整流程；文档配置、能力开关、实际运行和日志统计必须一致。正式公网发布不由开发试用更新自动推定。
