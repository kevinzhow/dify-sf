## 已改的共享规则

| 问题 | 修复与来源 |
|---|---|
| 标签输入 300px 里少一行 | 使用打包字体的 OpenType 平均宽度及最大字形边界重现原生 input size=20 的固有宽度；保留镜像随长输入伸展。原版和新 Wasm 都为 300×60，两行。输入底色在 Web 读取宿主浏览器显式 color-scheme 的原生值。 |
| 日历每行过高 | 按真实 16px 文本行与上下各 8px 内边距组成日单元；恢复 30px 月切换按钮。原版面板与 Flutter 绘制面板均为 289px；Flutter 夹具键还包含外部 4px margin，不能将其当面板差异。 |
| 小数描边 | 宿主浏览器原生计算 0.5px border 的实际宽度，按宽度和 DPR 缓存后给 Wasm；临时不可见测量节点立即移除。模拟 DPR 与物理 DPR 的舍入不能混用。 |
| CSS 透明度契约 | token 生成器保留 CSS 小数 alpha，不先取整；Wasm 引擎 Paint 仍转成 ARGB32，实际深色输入像素仍有每通道最多 1 个色阶的差异，失败证据保留。没有将某张截图 RGB 写成特殊值。 |
| 半透明卡片发灰 | Flutter 原生 BoxShadow 会画在半透明背景下面；Css.boxDecoration 共用绘制器按 CSS 将外阴影从 border box 内部剔除，保留外侧阴影，不改布局。透明白卡片内部保持白、外侧仍有阴影的实际栅格回归通过。 |
| 表格差 2px | 原生 td 默认 padding=1px、th 默认 bold；组件恢复默认，已有业务表格显式 p-* 的行继续显式提供 cellPadding。 |
| 退出循环描边 | SimpleNode 的源外框是 2px，普通节点仍为 1px；Widget 与 Scene 共用布局值。 |
| 人工表单缺应用外壳 | 复用原表单内容，补应用图标和标题、720px 卡片、期限、品牌页脚及原版状态页。paragraph 必填只用于公共表单，控制台／调试的既定校验不变。原生 inline textarea 的下沿基线和文字 strut 下伸量由现有字体度量计算，不加固定偏移。 |
| 供应商入口结构与导航 | Studio 的 Integrations 打开保留主导航的完整页面；编辑器的供应商设置仍是原版相应弹层。当前导航的蓝色玻璃表面复用源 CSS 渐变、环与阴影。焦点圈只绘制，不改变标签布局。 |
| 保存时间 | 编辑器标题复用账号时区的 AccountTime；实际 Home→editor 测试覆盖纽约／东京同一时刻。 |

## 设计系统归属

共享导航 MainNavLink、DifyBlueGlassSurface、DifyChatBubbleSurface、DifyBrandingFooter、DifyInlineReplacedBox 均放在 `app/lib/src/design/`，业务页面只组合内容和状态。单步人工表单复用 HumanInputContentItem，避免再保留另一套 textarea 和 Markdown 布局。来源清单检查会拒绝在业务层重复定义同名的公开共享控件；它不是“自动证明没有所有可能的重命名副本”。

按固定原版和相同字体规则修复，没有逐文案偏移、截图遮罩、排除文字、改阈值或改图。

外阴影裁切遵循 [W3C CSS Backgrounds and Borders 的 box-shadow 定义](https://www.w3.org/TR/css-backgrounds-3/#shadow-shape)：外阴影在 border box 内部被剔除。这是通用绘制语义，不是某张截图的颜色补偿。
