# Shared code-editor wrapping

The editor family has one application entry point, `CodeEditorView`. It keeps the original `CodeDocument`, Monaco Monarch token styles, `CodeEditing` commands, indentation detection and source-backed chrome. Re-Editor 0.10.0 provides Flutter input/gesture/undo plumbing through a reviewed MIT fork. Monaco's browser package documents that mobile browsers are unsupported; embedding it would also create a separate DOM/font path. A CodeMirror prototype was evaluated, but did not provide the same Flutter/native renderer. This change reuses an existing native editor instead of creating another input implementation.

Dify's pinned Monaco 0.52.2 defaults govern line breaks and continuation indentation. `wrapping.dart` ports the original monospace projection; the checked-in oracle records its source SHA and 312 cases. Soft wrapping is a view operation: raw source text, tabs, newlines, clipboard data and UTF-16 offsets remain unchanged. Only rendered tab cells and continuation indentation are projected. Original spans, including token/bracket styles and composing underlines, are sliced into visual rows.

One `IParagraph` serves drawing, hit tests, caret offsets, selection rectangles, word/row boundaries and input-method geometry. It resolves wrap-boundary affinity consistently. The original Dify menu and scrollbar families own chrome; Re-Editor's platform defaults do not become product controls. Extra space below the last line is scroll extent, not layout padding that steals the interactive viewport.

The row-painter cache is bounded to 64 visual rows per logical line and paints only rows intersecting the canvas clip. Word-boundary layout is lazy. Retired painters are released after their current frame. Font arrival invalidates layout while preserving the focused input, raw source and composing region. Theme changes invalidate cached spans and line-number colors.

Focused acceptance covers the original editing/token/document rules, all 312 original wrapping vectors, both affinities around wraps, supplementary Unicode, tab preservation, real text-input channel composition and undo, pointer clicks on a continuation row, clipboard source, read-only mobile keys and a system-font-change event. This is functional/layout evidence; comparison with Dify's actual code panels and complete application/device acceptance remain separate release gates. Neither native widget tests nor Chromium device emulation prove physical Android/iPhone performance.

The fixed Dify reference is 1.17.1, commit `8387590ace4a094de812b7847fc6a4c3a27cd52b`. Its own workspace design package is `@langgenius/dify-ui` 0.0.1, resolved by `workspace:*` in the Web dependency manifest. Design/reference hashes are recorded separately from third-party editor hashes; changing one requires explicit review. No pixel thresholds, text masks or synthetic per-line font offsets are introduced.

Dify’s text input uses the canonical complete-document full-state channel on every platform. This removes ambiguity between a current-line input buffer and a multi-line document selection; the pinned Web semantics strategy also lacks `beforeinput` hooks required by delta input. Actual browser insertion/composition is validated in addition to widget channel tests.

The platform input buffer is the complete canonical UTF-16 document, matching its semantic value and global selection. A complete-document controller hook reuses the existing Monaco formatter/undo; composing rectangles are projected back to the native base line. Selection-only updates cannot replace document text. The generic vendored controller retains its original delta default for other hosts. Read-only input connections expose selection while rejecting edits.
