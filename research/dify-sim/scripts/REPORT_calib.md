## 4. 校准（等价性证据）

**方法**（`calib/record.py`，直接 import 并复用 repro 的 Playwright harness，未修改它）：真实 Chromium（≤4 个同时会话）打开本机 Dify，记录①每个标签页每一帧 websocket 的时间 / 方向 / socket.io 事件名 / 大小（Python 代理处），②页内探针（`requestAnimationFrame` 回调时刻、画布节点 DOM 变化时刻），③运行前后的完整草稿 JSON。然后在模拟器里按**同一事件顺序回放**（`src/calib/replay.ts`）：每个标签页的提交时刻取自录制、每条更新的"服务端+代理"延迟取自录制；模拟器内每轮回放 30 个不同 seed（帧相位、peer id 随机）。比较：①结果类别分布（预测概率 vs 真实结果）；②真实存档与模拟存档**归一化后逐字节比较**（丢弃 `_` 私有键、`selected`、ReactFlow 的 DOM 测量字段 width/height/positionAbsolute/dragging/zIndex，把 null/undefined/缺失视为同一、键排序、坐标取 3 位小数；`hash` 本身不可直接比较，因为真实节点带 DOM 测量值）。"校准主线程"用**同一批真实运行**测得的"代理转发→画布 DOM 更新"延迟分布（p10 39 / p50 54 / p90 75 / max 90 ms，30 个样本）替代理想帧格。

**校准发现并修复的保真缺口**（这些在校准前模拟器与真实不一致，是"证据驱动修正"而非拟合）：
1. **ReactFlow 画布更新路径**（上文要点 1）：模拟器原先让 rAF 导入回调直接写画布，窗口只有 1 帧；改为与真实一致（回调对画布无效，只有 `graphImport` 写）后，S1N 校准档与真实一致。
2. **关页顺序**：真实 S5A（leader 关页且有他人在线）20/20 丢、S6A（单人）20/20 保存 → 页面关闭时 `visibilitychange→hidden` 先于 `beforeunload`，"隐藏的 leader 仅当房间里只剩自己才允许 flush"。
3. **"跳转"**：repro 的 S6D 用 `page.goto`，是整页导航（beforeunload 保存），不是 SPA 路由卸载（我最初按 React 卸载顺序推断"不会保存"，被真实 20/20 保存证伪）。SPA 卸载路径 `Tab.navigateAway()` 未对照真实浏览器验证，已在 FIDELITY 标明。
4. **选中状态**：点节点会给所有节点写 `data.selected`，顶层 `selected` 会被整节点写入 CRDT，存档体积 +25%；这决定了 S6F（100 节点 ≈72 KB）超出 keepalive 64 KiB（真实 19/20 丢，模拟 120/120）。
5. **指标口径**：被遮罩拦下、根本没出现在本人画布上的编辑记为 M5，不再算 M1（S4B 真实"被拒绝，非静默"）；S8 的外部写入进入账本（真实丢的是外部修改）。
6. **打开方式**：harness 逐个打开标签页并等就绪，所以 A 恒为 leader；并行打开会让 leader 随机，S3C/S4D 因此偏离。
7. **两个实现缺陷**（逐位等价检验抓到，见 §3）以及 `visibilitychange` 在 AsyncLocalStorage 之外触发导致处理器抛错（会让 S5A 类场景"碰巧"丢失）。
8. 真实环境参数：harness 代理使 A→B 端到端延迟中位 76 ms（不是本机回环的 1 ms）；代理转发到页内 JS 的额外延迟在负载高时可达数百毫秒——所以"代理时间线"只用于定序，延迟分布单独测量。

**仍未解决的差异**（如实列出）：
- S2O 自然时序：模拟 64/120（53%，[44–62]）vs 真实 19/19 → 39/39（repro 报告）。原因（推断）：模拟从 40 个真实样本里**独立**抽"双方提交时间差"和"加→重命名间隔"，丢掉了两个 Playwright 动作共享同一事件循环造成的相关性；用录制的**真实顺序**回放则是 100%。
- S6G（30 节点关页）真实 2/20 丢、模拟 0：repro 认为无法区分产品还是关页时序，我们同样无法解释。
- 面板 `inputs` 过期窗口只测到"<300 ms"，模拟器用 0~54 ms 的参数，未做更细标定。
- 真实主线程延迟随机器负载变化；校准分布来自本机一次测量（负载偏高），不是产品基线。
